# 録音直後の簡単なズレ調整

実装先は`pocket-booth-public`。GitHubへのpush、本番・テストサイトへのデプロイは行っていない。実機診断サイトでの測定・JSON提出を必須にするフローは使用しない。

## 変更

- 録音停止・保存処理後、制作画面の下に小さい「声のズレ調整」を表示。
- 選択した声の「−10ms」「＋10ms」「リセット」「聴いて確認」を用意。
- 再生中も調整可能。ビートを再スタートせず、対象クリップの再生だけを予約し直す。元の録音は変更しない。
- 既存トラック設定の調整も同じ`setClipCorrection()`と既存の`c.correction`を使用。二種類の手動補正を重ねて管理しない。
- 「次の録音にも使いたいとき」を開いて明示的に保存した場合だけ、その曲の新しいテイクへ初期値を設定。
- 初期値を0に戻しても、今あるテイクの補正値は変更しない。別の曲には共有しない。

今回の実装ファイル：`dist/app.js`、`dist/index.html`、`dist/style.css`、`dist/media-import.mjs`。追加テスト：`tests/browser-quick-timing.mjs`。既存の`tests/media-import.test.mjs`へデコード時のバッファ切離しに対する回帰テストも追加。

## データと互換性

自動補正済みの開始位置`c.start`と、手動補正ms`c.correction`を引き続き別に扱う。実効位置は既存どおり`start + correction / 1000`で、一度だけ適用する。リセットは手動補正だけを0に戻す。

初期値はプロジェクトの任意項目`recordingCorrectionMs`へ保存。古いプロジェクト・バックアップで欠けていれば0。新しく録音したクリップの`correction`に初期値を一度設定し、既存クリップや全トラックへの一括反映はしない。

既存の保存・再読込・WAV・バックアップは同じクリップ補正を使用。バックアップ形式はversion 3のままで、初期値の任意項目だけを追加。元Blob、PCM、録音Worklet、自動補正の計算は今回変更していない。

## iPhoneでの確認手順（承認後に反映した版で実施）

1. ビートを読み込み、いつもどおり声を録音して停止する。
2. 下に「声のズレ調整」が表示されることを確認する。
3. 「聴いて確認」を押す。対象の声が始まる約1秒前から、普段のミックス設定で再生する。
4. 声が遅ければ「−10ms」、早ければ「＋10ms」を数回押す。再生中も変更できる。
5. 「リセット」で0msに戻ることを確認する。対象の手動調整だけがリセットされる。
6. 他のクリップの位置が動かないことを確認する。ミュート・ソロを使っている場合、聴こえるトラックはその設定に従う。
7. 必要な場合だけ「次の録音にも使いたいとき」→「この値を次回の初期値にする」を押す。次のテイクだけがその値で始まり、前のテイクは変わらないことを確認する。
8. 曲を閉じて開き直し、補正が残ることを確認する。WAVを書き出して同じ位置で聴こえるか確認する。

閉じたパネルは、声のクリップ／トラック設定から「再生しながらズレ調整」で開ける。iPhone Safariでの実際の聴感・タップ操作は未検証。

## ローカルテスト

```sh
node --test tests/*.test.mjs
```

ブラウザ試験（PlaywrightとChromiumの場所は環境に合わせる）：

```sh
SITE_URL=http://127.0.0.1:4179 \
PLAYWRIGHT_MODULE=/opt/codex/cua_node/lib/node_modules/playwright/index.mjs \
CHROMIUM_PATH=/usr/bin/chromium \
node tests/browser-quick-timing.mjs
```

再生中の選択クリップだけの更新、元BlobのSHA-256と自動補正位置の保持、初期値の明示保存と次テイクへの適用、WAVの予約位置、再読込、320pxで44px以上の主要ボタン、旧バックアップ復元を検査する。

## バックアップ検査で見つかった読み込み不具合

既存の`importMedia()`は、デコード後のArrayBufferから保存用Blobを作っていた。ブラウザが`decodeAudioData()`の入力を切り離した場合、再保存する元データが空になることを合成音声のブラウザ試験で確認した。デコード前に保存用Blobを確保する修正を追加した。これは録音の加工や補正変更ではない。すでに空になっている過去のデータを復元する機能ではない。

最終結果：ユニット46件成功。簡単調整のブラウザ試験（再生中の選択声だけ更新／保存／WAV／次回初期値／旧バックアップ／元データハッシュ／320px操作）、既存の5回録音ライフサイクル、長押し移動・開始位置保護のブラウザ試験が成功。iPhone Safari実機の音と操作は未確認。
